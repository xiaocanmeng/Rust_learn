# GitHub MCP Connector 使用说明

本文件介绍 GitHub MCP Connector 的基础能力，内容为纯文本版本，避免使用代码块与特殊字符，以确保仓库写入稳定性。

## 1 主要能力概览
GitHub MCP Connector 提供以下几类功能：

1 读取类功能
可以安全读取仓库内容，适用于 public 和 private 仓库。包括读取文件、读取目录、查看分支、查看提交、查看 PR 信息、搜索代码等。

2 写入类功能
仅在 public 仓库中允许写入。在 private 仓库中会被安全策略阻止。写入类能力包括推送文件、创建或更新单文件、创建分支、创建 PR 等。

3 协作类能力
可以对 Issue 或 Pull Request 添加评论，也可以请求 Copilot 进行审查。

## 2 读取类能力细节
读取类能力通常不会触发安全限制，包括：

- 读取文件内容和目录结构
- 获取分支列表
- 获取提交历史
- 查看 PR 内容和状态
- 搜索代码或 Issue

这些能力可在任何仓库中使用。

## 3 写入类能力细节
写入类能力包含推送文件和更新文件等。注意：

- 仅限 public 仓库
- 在 private 仓库中使用写入能力将被安全策略拦截并返回 403 错误

## 4 协作类能力细节
协作功能主要用于开发流程支持：

- 对 Issue 或 PR 添加评论
- 创建或更新 Issue
- 请求 Copilot 审查 Pull Request

这些功能在 public 和 private 仓库均可使用。

## 5 限制与注意事项
- 无法通过 Connector 创建 GitHub 仓库
- 无法对 private 仓库执行任何写入操作
- 读取操作几乎不受限制
- 若要进行自动写入，建议使用 public 仓库的独立分支

## 6 使用建议
推荐在 public 仓库中创建一个专门分支用于测试 MCP 写入操作，例如 dev 或 mcp docs。
在 private 仓库中，建议由模型生成内容后再由用户手动复制进入仓库文件中提交。
